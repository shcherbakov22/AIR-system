# Domain Model

## Core Entities

### User

A user is the authenticated account.

Current human roles:

- mentor
- student

The code may still use `admin` internally for compatibility, but the product role is mentor.

### Student

A student profile belongs to a user and holds student-facing identity data such as display name and settings.

### Task Template

A task template is the reusable catalog item students and mentors schedule against.

It defines:

- title
- default duration
- optional instructions

### Schedule Template

A schedule template is the saved schedule definition.

In the current product:

- students own their own schedules
- mentors have separate schedule-template management for planning/admin work

### Schedule Entry

A schedule entry is one planned block inside a saved schedule.

It carries:

- position
- task template
- planned duration
- optional notes

### Schedule Run

A schedule run is the live execution instance of a schedule.

It is created when a student starts a schedule from the dashboard.

### Schedule Run Block

A schedule run block is the per-block runtime copy inside a schedule run.

It tracks:

- block position
- current status
- started/completed timestamps
- planned duration
- actual duration through linked task session activity

### Task Session

A task session is the actual running timer/activity record.

It may represent:

- a schedule block in progress
- a custom timer started while a schedule is paused
- a legacy/historical assignment-linked session

### Rule Definition

A rule definition is the mentor-managed definition of a behavioral rule.

Current rules are global in product behavior.

### Violation

A violation is a concrete event recorded against a student.

Violations can be:

- mentor-created
- automatically generated by the time-observance logic

Open violations can block student schedule actions.

### Student Monitor Capture

A monitor capture is a stored screen or camera image tied to a student and a point in time.

It may include:

- capture kind
- capture time
- upload time
- task snapshot
- source label

### Speech Announcement

A speech announcement is a queued line for the mentor monitor browser to read aloud.

## Important Runtime Relationships

- a student owns many schedules
- a schedule has many entries
- a student can have many schedule runs over time
- a schedule run has many schedule run blocks
- a running block is represented by a task session
- a student can have many violations
- a student can have many monitor captures

## Important Rules

- only one active task session should exist for a student at a time
- only one active or paused schedule run should exist for a student at a time
- students may start unfinished schedule blocks out of order
- students may finish a schedule early with unfinished blocks left incomplete
- open violations can block continuing work
- automatic `Observe the time` violations should only be generated once per incident
